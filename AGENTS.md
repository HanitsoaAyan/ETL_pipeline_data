# AGENTS.md

ETL pipeline **extraction + load** module. `extract.py` (Extract) reads sources and writes traceability copies to `raw/`; `Load/` (Load) reads the transformed data in `clean/` and loads a star-schema MySQL data warehouse (`datawarehouse`). The Transform outputs (`clean/`) are generated by a separate repo but committed here. README and data labels are in French. No tests, lint, or CI.

## Setup & run

```bash
python3 -m venv venv && source venv/bin/activate
pip install pandas sqlalchemy pymysql neo4j python-dotenv   # no requirements.txt / lockfile, versions unpinned
mysql -u root -p < basededonner.sql                          # create MySQL DB "operateur" + table "utilisateurs"
python extract.py
# then, for the DW:
mysql -u root -p < Load/warehouse_schema.sql                 # create DB "datawarehouse" + 4 tables
python Load/load_dw.py                                       # reads clean/, loads dims + fact_order
```

`extract_db` only reads; the MySQL DB and Neo4j instance must exist and be populated beforehand.

## Gotchas

- **`extract.py` `__main__` runs only `extract_db` + `extract_neo4j`** (extract.py:78-95). The root `customers.csv`/`orders.json`/`products.csv`/`reviews.json` sample sources are NOT extracted by the script, despite README claiming all sources run. The four `extract_*` functions are standalone and unwired.
- **MySQL password is hardcoded** in extract.py:79 (`mysql+pymysql://ayan:Ayan123!@localhost:3306/operateur`). A committed secret — do not propagate it; align it with the local DB or move it to `.env`.
- **Neo4j creds come from `.env`**: `NEO4J_URI`, `NEO4J_USERNAME`, `NEO4J_PASSWORD`, `NEO4J_DATABASE` (default `neo4j`). README references `.env.example`, but it does not exist in the repo — create `.env` from scratch. `.gitignore` only lists `.env`.
- **`raw/` is tracked in git** even though README says it's excluded. Every `extract_*` call writes a traceability copy to `raw/<run_id>/<filename>`; run_ids are fixed strings (`run-utilisateurs`, `run-relations`, ...).

## Load / Data Warehouse

- **`clean/` is a stale-clone trap**: it exists on GitHub `main` but may be missing locally until you `git fetch origin && git checkout origin/main -- clean/` (or branch from fresh `origin/main`). The transformed customer file is literally named ` customer_clean.csv` (**leading space**); `load_dw.py` locates it by scanning the dir.
- **`fact_order` has NO `product_id`**: orders (`orders_clean.json`) don't reference products. This is deliberate — the mission forbids inventing input columns. `dim_product` is loaded but unlinked. `load_dw.py`'s column mapping is alias-based (`Load/load_dw.py` `CLIENT_COLUMNS`/`PRODUCT_COLUMNS`/`ORDER_COLUMNS`) and accepts EN/FR headers.
- **DW credentials come from `.env`**: `DATABASE_URL` (only honored if set in the `.env` file, not the shell) or `DW_DB_HOST/PORT/USER/PASSWORD/NAME`. `database.py` builds the engine via `sqlalchemy.engine.url.URL.create`, so passwords with special chars (`!`) work.
- **Load is idempotent**: `DW_RESET=1` (default) deletes all 4 tables before reloading. Every dim gets an "unknown" row (`id 0`) so any fact FK reference that's missing from a dim never violates constraints.
- **`utilisateurs_clean.json` and `relations_clean.json` are incomplete** (2 rows each — flagged in `clean/README .md`); they are not part of the DW load.
